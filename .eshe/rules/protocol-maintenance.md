# Change the protocol and integrations deliberately

Protocol documents, local preferences and vendor skills evolve independently. Record installed Eshe version/origin, local overrides and active profile versions in the authority map. This version supplies no installer, executable adapter or hook.

## Adoption and coexistence

Inventory existing AGENTS/instruction files, spec systems, task trackers, memory and hooks. Choose one owner for requirements, decisions, task state and evidence. Eshe may point to existing OpenSpec/Spec Kit/other artifacts; do not create two competing task schedulers or duplicate specs. Preserve host instructions. Vendor commands are examples until their actual capability is verified.

Before activating an integration, fill [the adapter contract](../templates/adapter.md): supported host/version, available capabilities, actual read/write roots, instruction inclusion rules, permission boundary, data destinations, invocation mappings and fallback. Track checks as `manual`, `advisory` or `enforced` with proof of interception. An agent prompt or post-action hook cannot claim it prevented an already completed action. Missing enforcement is disclosed, not inferred from configuration text.

## Upgrade and exceptions

1. Compare installed version/local edits with the proposed source. Inspect origin, relevant changes and host compatibility; do not execute install instructions from fetched prose automatically.
2. Prepare a path-by-path difference, conflicts, new dependencies/permissions and evidence that needs renewal. Preserve accepted project decisions and task receipts.
3. Apply only an authorized local upgrade. Use create-missing or reviewed merges; snapshot affected records. Test link/schema compatibility, literal bootstrap and repeatability; recover only this upgrade's changes if it fails. Never reset unrelated work.
4. Record from/to version, actor, scope and validation. A changed rule reopens dependent work when applicable; it does not retroactively change old evidence.

An exception needs rule ID/source, reason, narrow scope, authority, compensating proof and expiry/reopen event. It cannot override higher-priority instructions or be granted by the agent outside delegated authority. An absent switch is unknown, not permission to enable external behavior.

## Lessons and hooks

Capture a recurring failure as a local proposal: evidence, cause, smallest rule change, expected benefit and regression scenario. Review for contradiction and context cost before adopting. Do not automatically edit global skills/memory, ingest personal histories, schedule jobs or publish the lesson.

If hooks are later requested, map session/resume to context refresh, before-action to verified preconditions, after-action to evidence capture, and close to reconciliation. Define timeout, recursion guard, failure handling and host coverage. Any required safety gate that cannot run blocks its dependent action; an optional advisory failure is visible. Hook installation, daemon execution, telemetry and external calls require actual authorization and implementation proof.
